# 中文注释示例与编辑注意事项

以下为独立的表达示例，不代表目标项目真实接口；只有确认目标实现具备相应约束时才能采用类似描述。

## 1. 解释原因与边界

无帮助的复述：

```c
/* 将计数加一 */
count++;
```

若变量变化已显然，直接保留代码即可，无需为了覆盖率加注释。

有依据的约束表达形式：

```c
/* 调用方持有 queue_lock，节点在移出队列前不会被其他路径释放。 */
```

该描述需要锁保护范围和释放路径证据；看到某个路径加锁并不够。无法确认所有路径时不要使用这句断言。

## 2. 与实现一致的 KernelDoc

```c
/**
 * clamp_count() - 将请求数量限制在可用数量以内
 * @requested: 请求的元素数量
 * @available: 当前可用的元素数量
 *
 * Return: 两个参数中的较小值。
 */
static unsigned int clamp_count(unsigned int requested, unsigned int available)
{
	return requested < available ? requested : available;
}
```

示例只说明 KernelDoc 格式；该简单函数在真实项目中通常不需要如此完整的注释。不为它添加“持锁”“可能睡眠”“非法返回 -EINVAL”等实现不支持的契约。

对于返回错误码、可空指针、异步持有对象或上下文受限的真实函数，应先读完整实现和调用路径，再补充对应字段。返回类型本身不能证明全部返回语义。

## 3. 成员与生命周期

以下表达分别需要核查初始化、读写、持有与回收位置：

- “缓冲区长度，单位为字节”需要确认该字段确实记录字节而非元素数。
- “由调用方持有，返回后仍需有效”需要确认是否存在异步引用及其结束条件。
- “由设备托管释放”仅说明托管资源归属，不证明 work/IRQ/timer 已停止。
- “在 lock 保护下访问”需要核查相关读写路径，不能由字段邻近一个锁推定。

枚举注释描述当前状态含义；只有写入点和分支证明转换关系时才描述可达状态或转换顺序。

## 4. 语法与工具边界

- C/C++ 注释定界符不能嵌套；注释内容中的终止符可能提前结束注释。不要在示例文字内无检查地嵌入定界符。
- 宏定义、反斜杠续行、预处理指令附近的注释需要检查逻辑行和 token 分隔，不能在宏行尾随意添加多行说明。
- shell 的 shebang、编码声明、工具标签和条件禁用标记保持原有意义；用项目语言原生语法，不把 C 风格注释强套到脚本。
- Python docstring 是运行时可访问的文档字符串，不能把其改写一概称为普通注释变化；doctest 示例也可能执行。
- Rust 文档注释可能含文档测试；Go 注释可能包含构建、生成或 cgo 指令。先识别标记用途，再决定可编辑部分。
- 不翻译许可证、SPDX 标识、寄存器位名、函数/参数名、协议字段、工具识别标记和日志字符串。普通解释文字才是中文化对象。

## 5. 交付复核提示

对照最终文件核查注释是否贴近对象、有无重复契约、实际参数是否匹配、异常/退出分支是否被误述。功能判断仍不充分时在交付中列证据缺口，不在源码里增加看似确定的保证。
