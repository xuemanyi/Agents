# Linux 内核源码事实分析

以当前可访问的真实源码为唯一的项目实现事实依据，还原组件关系、执行路径、数据流、生命周期与同步边界，供用户及其他 Skills 复用。

## 工作边界

- 仅做只读分析，不修改源码、配置、测试或构建文件；不为分析编译或执行目标代码，不加载/卸载模块，不读写设备接口，不执行改变系统或硬件状态的诊断操作。
- 默认直接回答。用户明确要求落盘时，可在授权路径写分析结果；这不授权修改被分析项目的实现文件。
- 不把潜在风险定性为缺陷，不产出缺陷报告、教学文档、SAD、SDD、SRS 或 FMEA。只客观记录已见路径、约束与证据缺口，必要时供相应能力继续判断；不自动委派或假定其他 Skill 存在。
- 定义、赋值及使用路径构成证据；函数名、注释、搜索匹配和通用内核知识只能提供检索线索，不能单独证明项目实际行为。
- 项目源码缺失时，先说明可见范围并索取必要路径/文件，不用其他版本、联网源码或运行内核替代目标项目事实。外部规范若用于解释语义，明确其不是项目实现证据。

## 1. 确立基线与范围

先从用户目标和现有上下文确定源码根目录、目标符号/事件/组件及需要回答的问题。信息可从已授权可见文件获得时先查证；缺失且实质影响结论时再询问，不猜测目标项目。

| 项目 | 只读核查 | 未知时处理 |
| --- | --- | --- |
| 路径与修订 | 工作区路径、`git rev-parse --show-toplevel`、`git rev-parse HEAD`、`git status --short`、相关 Diff | 标注非 Git 或修订未知；工作区内容不等同于已提交基线 |
| 内核版本 | 根 Makefile 的版本字段，必要时 `git describe` 或已有版本头 | 写“代码中未确认”；`uname` 不能代替源码版本 |
| 架构 | 用户提供的 ARCH/构建命令、平台配置和实际架构实现 | `arch/` 存在某目录不代表该架构已选中；仅描述可见分支 |
| 配置 | 已有 `.config`、指定 defconfig、Kconfig、编译宏及已有构建记录 | 区分实际配置、候选默认值和未知条件，不把 defconfig 当作实际 `.config` |
| 分析范围 | 目标源码、调用/注册入口、Makefile/Kbuild 和相关头文件 | 列出覆盖范围、排除内容和缺失文件 |

使用 `rg` 限定目录检索符号，再读取定义、声明、引用和足够上下文；例如以 `nl -ba` 配合行区间读取获得稳定行号。搜索结果不是完整证据。

相关文件有未提交修改时，注明“工作区基于 <修订>，含相关修改”；引用以实际读取的工作区为准，必要时区分 HEAD 与工作区。长分析发现文件变化时复核受影响证据，不能混用不同基线的行号和结论。

## 2. 为重要结论建立证据链

每项重要结论包含：事实 ID、具体结论、源码位置与关键符号、配置/架构/状态前提及证据等级。多个位置共同构成结论时全部列出关键位置。

| 等级 | 使用标准 |
| --- | --- |
| 已确认 | 当前范围的定义、赋值和使用路径足以直接证明该结论 |
| 条件成立时确认 | 代码在明确的配置、宏、架构或分支条件下直接证明；必须写出条件及其是否已满足 |
| 静态推断 | 有源码依据，但缺少运行时绑定、动态状态或完整调用方证据；说明推断依据及缺口 |
| 代码中未确认 | 缺少必要源码，或无法排除多个解释；列出需要补充的证据 |

- 引用格式：`drivers/foo/bar.c:120-138`，注明符号；路径相对已声明源码根目录。必要时附可点击路径，保留可复核的位置。
- 行号必须来自实际读取；缺少行号时先补查，仍不能取得则写“位置待定位”，不编造数字。
- 将结论限定到证据真正支持的粒度。例如，“存在调用表达式”不等于“运行时已执行”，“有一次释放”不等于“所有退出路径均释放”。
- 注释与实现不一致时以执行代码为准；仅记录观察到的不一致，不延伸为缺陷定性。
- “未检索到”须限定检索范围，不等于全局不存在。未知配置不视为启用，编译进入目标不等于初始化、注册或执行成功。

## 3. 区分调用、注册与执行触发

从目标定义及其编译入口出发，向上追踪调用者、注册者或事件来源，向下追踪被调函数、关键状态变化及返回路径。

| 边类型 | 必需证据 | 表达方式 |
| --- | --- | --- |
| 直接调用 | 调用表达式、目标定义、符号解析及适用编译条件 | `A --直接调用--> B` |
| 函数指针 | 成员/变量声明、初始化/赋值、可见覆盖及调用点 | `A --经 ops->fn 间接调用--> B（候选/已绑定）` |
| 回调注册 | 注册接口实现、回调实参、返回/失败处理、注销位置 | `注册方 --注册--> callback`；执行入口另列 |
| 异步执行 | 对象初始化、回调绑定、提交/启动、执行分发及取消同步 | `提交者 --调度--> work`；`执行器 --异步触发--> callback` |
| 跨模块交互 | 导出符号与链接关系、通知链、消息或设备接口的发送/接收路径 | 标注具体机制，不把消息传播画成直接调用 |

- 分开描述“源码传入回调”“注册成功的条件”和“事件何时执行回调”。注册调用不证明运行时成功，调度不证明回调已执行。
- 对 ops、函数表和回调数组追踪当前范围内所有可见赋值及条件；多个目标逐项列出。静态绑定和动态可重绑定分别说明，不把单个初始化值当作永远不变。
- 追踪 `#if/#ifdef`、Kconfig、架构特化、宏/内联包装、弱符号及可选模块；仅在符号解析证据充分时确认目标。
- IRQ、work、timer、tasklet、hrtimer 等分别追踪初始化、提交、执行和停止路径；封装层次过多时展示关键节点和可展开证据，不无限展开辅助函数。
- 动态注册、外部模块、运行时重绑定或按名查找无法穷尽时，写“当前源码范围内的候选”；将“可能可达”“条件成立时可达”与“已证明的源码关系”分开，不声称运行时实测或全局完整。
- 只有跨组件或关键分支有助理解时绘图。默认 Mermaid `flowchart`，标明边类型、条件及推断/候选；仅有明确时序证据时使用 `sequenceDiagram`。图不得比文字证据更确定。

## 4. 追踪关键数据流和控制流

- 标识输入：参数、设备树/ACPI、寄存器、用户缓冲区、DMA、共享或全局状态；标识输出、返回值及外部可见状态。
- 按实际路径追踪关键赋值、转换、拷贝、校验、状态迁移、分支、短路、循环退出与错误返回，保留相关条件编译和异常分支。
- 区分指针别名、共享对象、深拷贝与所有权转移；所有权不能仅由指针传递推定。必要时追踪写入者、读取者及引用的存续时间。
- 总结决定结论的关键节点，每个节点给源码位置；无关底层辅助函数可作为边界，注明尚未展开的部分。

## 5. 建立对象与资源生命周期

对目标相关的关键对象记录：

1. **定义与创建**：类型、存储位置、分配/映射/注册方式、失败结果。
2. **初始化与发布**：字段赋值、发布位置、其他上下文开始访问的条件及同步证据。
3. **使用与持有**：主要读写路径、持有者、所有权与引用计数的增减。
4. **异步关联**：IRQ、workqueue、timer、RCU、DMA、等待者和回调如何取得及保留引用。
5. **异常路径**：部分初始化失败、回退标签、仅已获取资源的清理及实际顺序。
6. **退出路径**：撤销发布、注销、同步等待、释放；devm 资源另查所属设备生命周期和相关释放机制。

不能仅凭 `devm_*` 推断异步使用已结束，不能仅凭存在 `kfree()` 推断所有退出路径可达。只报告观察到的资源操作、顺序和缺口，不定性泄漏、UAF 或死锁。

## 6. 确认上下文与同步约束

- 从实际入口/分发路径判断进程、hardirq、softirq、workqueue、timer 或内核线程上下文；存在多入口时分别列出，不用函数名代替入口证据。
- 根据调用路径、锁类型、IRQ/抢占状态及相关配置说明睡眠约束；缺少调用方证据时只列必要限制，不宣称“一定可睡眠”。
- 对 mutex、spinlock、rwlock、atomic、RCU、completion、waitqueue 等，定位保护对象、获取/释放或读写/等待/唤醒位置、当前可见嵌套和顺序；不能由“有锁”推定所有访问都受保护。
- 区分并发来源：多线程、IRQ、异步任务、用户并发、热插拔、卸载与错误恢复；区分实际已证实来源和条件性来源。
- 仅陈述代码可证明的先后顺序和同步边界，不由单一路径推断全局无竞争；未展开的同步原语实现或架构语义注明边界。

## 7. 核查构建与外部依赖

按相关性定位 Kconfig、Makefile/Kbuild、导出符号及模块依赖，说明配置为 `y`/`m`/未启用或未知时的差异（仅在源码支持且影响结论时展开）。

分别标记：

- **头文件依赖**：声明与类型来源，不证明实现被链接或实际执行。
- **编译/链接依赖**：构建目标、条件和符号实现，不证明运行时绑定。
- **运行时调用/绑定依赖**：子系统注册与匹配、设备树/ACPI、寄存器、IRQ、DMA、固件、用户态 ABI 或工具的实际使用路径。

缺失硬件描述、固件或用户态文件时列为证据缺口，不用通用平台知识补成项目事实。

## 8. 输出与复核

单函数/局部查询优先给精简事实卡：基线与范围、功能事实、关键调用/状态/约束、证据等级和未确认项。只包含与问题有关的内容。

跨模块或完整链路任务读取 [报告与交接模板](references/report-template.md)，按范围裁剪。保留事实 ID、条件和原始证据，便于其他 Skills 复核；不自动生成其他专业交付物。缺少证据的相关章节写“代码中未确认”，范围外章节可省略或写“不在分析范围”。

交付前核对：

- 基线与实际覆盖范围明确；工作区修改、未知架构/配置未被隐去或假定。
- 重要结论有真实位置；证据等级、条件、多个候选及动态绑定缺口可见。
- 直接调用、间接调用、注册、调度和执行未混淆；图表不扩大证据确定性。
- 生命周期覆盖相关正常、异常及退出路径；上下文和同步结论有入口及操作证据。
- 未修改项目，未执行目标/硬件诊断，未作缺陷定性或输出其他 Skills 的最终文档。

范围过大时先交付边界明确的事实和待扩展入口，写清未覆盖部分；不要以完整但未经证明的故事填补空白。
