# 专题定位要点

按故障类型只读相关部分。以下是证据调查方向，不是工具已安装、运行已获授权或问题已发生的声明。具体 API、锁、异常编码和硬件语义依目标源码/架构及匹配官方资料核对。

## 崩溃、Oops、panic 与 WARN

- 找最早有效异常及此前日志，区分主动 BUG/WARN、异常处理和后续 panic 策略；不要仅由最终 panic 符号定位最初错误。
- 核对实际 faulting instruction、寄存器、访问地址与源表达式；低地址不能独自证明 NULL，异常地址也不能独自证明 UAF。
- 堆栈证明所捕获的执行现场，不必然给出所有历史事件；注意截断、不可靠帧、优化、内联和可能的栈损坏。
- 使用已有且匹配的 `vmlinux`、模块与调试信息解码。按当前树中工具实际用法选择解码脚本、addr2line、objdump、gdb 或 crash；不假定命令选项，不向分析工具自动加载来源不明的命令脚本/扩展。
- 缺少未剥离产物、模块加载信息、地址偏移或匹配架构时，保留可确认的符号/偏移并列精确定位缺口；不能从错误版本强行解析行号。

## 内存、引用与边界

- 对检测器记录保留报告类型、访问大小/方向、访问对象、分配/释放栈和时间关系（材料具备时）。不要把报告格式套用于缺失字段。
- 从分配、发布、持有、借用、引用增减、取消/同步与释放证明对象生命周期；存在同名变量或相似地址不代表同一对象，考虑对象复用的可能性。
- 检查长度/索引、整数转换、拷贝边界及相关失败分支；区分用户地址、内核虚拟地址、物理/DMA 地址，不能无依据互相转换。
- `devm_*` 不证明异步引用已终止，`kfree()` 存在不证明所有路径均释放，引用计数存在也不证明每个读写者均持有引用。

## 竞态、死锁、卡死与延迟

- 区分 lockdep 报告的依赖关系、现场实际等待、hung task、soft/hard lockup、RCU stall 和单纯响应变慢；不同证据不能互相代替。
- 对每个相关执行实体列上下文、持有/请求的锁、等待对象、唤醒者、IRQ/抢占状态和退出条件；同一对象的共享访问须有具体位置。
- ABBA 候选需要可行的获取顺序、对象身份和并发条件；不能把两个孤立锁操作直接写成已发生死锁。真实等待环与静态潜在环分别标注。
- KCSAN 等报告保留访问现场及工具限制；缺报不能证明无竞态。明确目标 PREEMPT/RT/SMP 条件后再解释锁/上下文行为。
- 卡死需区分丢失唤醒、条件永不满足、锁等待、忙循环、设备无响应和长期 I/O 等候选。单个任务栈不足以排除其他任务/CPU 或硬件原因。

## 驱动、IRQ、DMA 与平台

- 追踪 probe/注册、设备匹配、资源建立、IRQ/work/timer 启动、失败回退及 remove/unbind；区分注册请求与成功后可被触发的阶段。
- 检查 IRQ 与异步活动停止、同步边界和资源释放的具体先后关系；不能仅凭释放 API 存在宣称退出安全。
- DMA 核对映射类型/方向、长度、返回值、同步、所有权转移及 CPU/设备访问条件。平台一致性/IOMMU 和寄存器语义未知时保留硬件证据缺口，不用通用知识断言。
- 区分驱动逻辑、设备树/ACPI、时钟/电源/复位、固件、硬件时序和外部输入候选，依据资料逐项判断；不自行操作寄存器或总线验证。

## 回归与修复验证

- 核对好/坏版本的实际配置、补丁、工具链、模块、固件和负载，不能把环境差异误认成代码回归。
- 只读检查相关提交/Diff 可生成候选；某提交时间接近故障不是引入根因的证据。
- 用户授权 bisect 后才在隔离工作区执行可能改动检出的流程，不改写用户工作区；确保测试判据和每步结果真实可复查。无法判定的样本记为未知/跳过，不能强行记 good。
- 最小复现应保留关键时序/条件而非只打印 PASS。运行必须已获授权并有资源/时间上限和恢复方案；第一次达到停止条件就停止。
- 修复后编译通过仅证明该构建结果；复现消失是验证证据之一，仍需核对根因机制和相关异常/退出路径。
